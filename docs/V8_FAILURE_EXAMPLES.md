# Mini-ELF v8 — failure & success examples

Real lean-cli transcripts from `data/baselines/v8_eval/donorless_eval/seq2seq_only/`.
The seq2seq generated **582 candidates** (61 theorems × ≈10 each); **3 verified**
(all in `exists_reconstruct`); **579 failed**. The taxonomy is generated by
`scripts/analyze_v8_failures.py` against the cache-backed enriched
`predictions.jsonl`. Worked examples below were chosen one per
failure-or-success class.

## 1a. Successful cross-family generation (the headline)

### `neg_exfalso_pq` (held family `neg_exfalso`; train pool includes 9 sibling PB families + basic+hard)

**Goal.** `(p q : Prop) (hp : p) (hnp : ¬p) ⊢ q`.

**Seq2seq top-10 candidates (donor_available = False; held family is absent):**

```
0. exact hpq hp                     FAIL  (unknown identifier `hpq`)
1. exact And.int                    FAIL  (Lean: `And.int` undefined)
2. exact hp\n  ex                   FAIL  (malformed)
3. exact absurd hp hnp              VERIFIED ✓ (novel)
4. exact hpp hp                     FAIL
5. exact h.1 hp                     FAIL
6. exact hrp                        FAIL
7. exact h.1                        FAIL
8. exact h.mp hp                    FAIL
9. exact (hnp hp).elim              VERIFIED ✓ (novel)
```

**Why this verified — and why it counts as cross-family generation.**

- The held family `neg_exfalso` is entirely absent from train; the seq2seq has
  never seen the *exact* tactic strings `exact absurd hp hnp` or
  `exact (hnp hp).elim` paired with any theorem (`novel = true` for both).
- But the train pool contains **sibling negation families** — most importantly
  `neg_imp_exfalso` and `neg_or_cases` — which use the token `absurd` and the
  hypothesis-name convention `hp`/`hnp` in slightly different contexts.
- The model composed those tokens into a syntactically and semantically
  correct tactic for the held family. The mechanism is **token composition
  learned from sibling families**, not retrieval of a memorised string.
- The same pattern holds on 5 of 8 `neg_exfalso` test theorems
  (`pass@5 = 0.625`, `novel_verified = 9`, `cross_family_verified = 9`).

This is the first non-zero `cross_family_verified` on a v7 holdout regime in
the project's history. v7's retrieval-only `family_holdout` was uniformly
0.00 with `cross_family_verified = 0`; v8's seq2seq breaks that wall when
the train pool contains shape-compatible sibling families.

## 1b. Successful **operation**-holdout transfer (`intro_negation` op, held)

### `neg_double_intro_p` (held operation `intro_negation`; ALL theorems with that operation absent from train)

**Goal.** `(p : Prop) (hp : p) ⊢ ¬¬p`.

This is the harder regime: every theorem whose `required_operation` is
`intro_negation` is removed from train. The seq2seq cannot rely on
intro_negation training rows at all; it must compose from other operations.

**Seq2seq top-10 candidates (operation_absent_from_train = True;
family_absent_from_train = True):**

```
0. exact id                              FAIL
1. exact fun h => h                      FAIL
2. exact absurd hp                       VERIFIED ✓ (novel, cross-operation)
...
8. exact absurd hp                       VERIFIED ✓ (same string, beam dedupe edge)
```

**Why this verified — and why it's stronger than the family-holdout win.**

- The held operation `intro_negation` includes `neg_double_intro`,
  `neg_imp_exfalso`, `neg_contrapositive` — every "introduce a negation"
  pattern. **None** of those theorems are in train.
- The seq2seq still produces `exact absurd hp` and Lean accepts it: the
  type `α → ¬α → β` unifies with goal `¬¬p = ¬p → False`, treating the
  partial application's missing `¬α` argument as the goal's `¬p`
  hypothesis. The model never saw this exact term in training.
- Tokens used (`exact`, `absurd`, `hp`) were learned from **other**
  operations: `absurd` from `contradiction`-op rows (`neg_exfalso`,
  `neg_or_cases`) which use it with two arguments; `hp` from basically
  every negation training context. The model composed them into a partial
  application that Lean's type-inference completed — a genuinely new tactic
  string.
- This pattern verified on 3 of 16 `neg_double_intro` held theorems
  (`pass@5 = 0.125`, `pass@10 = 0.188`).

**`cross_operation_verified = 3`** here, on top of the
`cross_family_verified = 3` — v8 is the first model in the project to verify
*any* `cross_operation_verified` candidate, breaking the v7 wall on a
strictly harder regime than family-holdout.

## 1c. Successful donorless slot fill (the slot-fill mechanism)

### `exists_reconstruct_7` (held family `exists_reconstruct`; train pool = basic+hard only, **no** PB family)

**Goal.** The target is `∃ n, n = 7` with the hypothesis already in scope.

**Seq2seq top-5 candidates (donor_available = False):**

```
1. refine ⟨m, ?_⟩\n  rfl       FAIL  (unknown identifier `m`)
2. refine ⟨6, ?_⟩\n  rfl       FAIL  (Lean: 6 ≠ 7)
3. refine ⟨9, ?_⟩\n  rfl       FAIL
4. refine ⟨7, ?_⟩\n  rfl       VERIFIED ✓
5. refine ⟨5, ?_⟩\n  rfl       FAIL
```

**Why this verified.** The seq2seq learned the `refine ⟨N, ?_⟩\n  rfl` shape
from the basic-corpus `exists_witness` family (`exact ⟨0, rfl⟩` etc.) in
training. At inference it tried multiple literal slots (`5`, `6`, `7`, `9`,
`m`) — beam 4 was the right one. The verified tactic string is in the **train
tactic pool** (basic_lean_cli has `exact ⟨1, rfl⟩`, etc.), so
`novel_verified = 0`: this is an **open-vocabulary slot fill**, not abstract
synthesis. The cross-family condition is real (`exists_reconstruct` is not
in train) but the proof *shape* overlaps `exists_witness` training data.

### `exists_reconstruct_100` (same family, different literal)

**Top-5 candidates:**

```
1. refine ⟨10, ?_⟩\n  rfl       FAIL
2. exact ⟨10, rfl⟩              FAIL
3. exact ⟨100, rfl⟩             VERIFIED ✓
4. refine ⟨100, ?_⟩\n  rfl      VERIFIED ✓
5. refine ⟨0, ?_⟩\n  rfl        FAIL
```

Both `⟨100, rfl⟩` slot fills verified. The seq2seq's beam diversifies
literals from the goal context — the model learned the slot during
basic-corpus training even though the *family* (`exists_reconstruct`) was
absent.

## 2. Failure taxonomy — one worked example per class

### Class: `wrong_theorem_family` (uses a hypothesis name absent from the target)

**`neg_exfalso_pq`** (held family `neg_exfalso`; available hyps: `hp : p`, `hnp : ¬p`)

**Top-3 candidates** (all from `proof_block_seq2seq`):
```
1. exact hpq hp        FAIL — unknown identifier `hpq`
2. exact And.int       FAIL — Lean: `And.int` not a declaration
3. exact hp\n  ex      FAIL — malformed
```

The seq2seq hallucinated `hpq` — a name common in **other** training-pool
theorems (`and_intro`, `imp_uncurry`) but not in this target. The correct
move would be `exact absurd hp hnp` or `contradiction`; the model did not
emit either.

### Class: `wrong_binder` (right-shape destructor, wrong arity)

**`neg_or_cases_pq`** (held family `neg_or_cases`)

**Top-3 candidates:**
```
1. rcases h with\n  | inl hp => exact hp\n  exact hp     FAIL — wrong branch
2. rcases h with hp | hp\n  exact hp\n  exact hp         FAIL — mismatched
3. cases h with\n  | inl hp => exact hp\n  exact hp      FAIL — mismatched
```

The seq2seq emitted a *plausible* `rcases ... with ...` shape, but the
destructuring pattern doesn't match the target's disjunction structure
(both branches bind `hp` to the same name without using the negation
hypothesis the family requires).

### Class: `wrong_exists_destruct` (right operation, wrong projection)

**`exists_elim_prop_p`** (held family `exists_elim_prop`; target's hyp is `h : ∃ x, p x`)

**Top-3 candidates:**
```
1. exact h.left      FAIL — type mismatch: h is ∃, not ∧
2. exact h.right     FAIL — same
3. exact h.1         FAIL — same
```

The seq2seq is treating the existential as a conjunction (the `∃` and `∧`
shapes are textually similar in our basic-corpus training rows). All three
candidates are valid for `∧`-elimination — none for `∃`-elimination.

### Class: `missing_intro` (negation goal needs `intro` first)

**`neg_imp_exfalso_pq`** (target: prove a contrapositive without `intro` first)

**Top-3 candidates:**
```
1. exact fun h => hp     FAIL — λ-style attempt, missing intro
2. intro h\n  exact hp   FAIL — wrong direction
3. exact fun h => h      FAIL — identity, wrong term
```

The seq2seq did *one* `intro h` (candidate 2) but the body still references
`hp` which is not introduced yet at that point. The correct sequence requires
deeper structuring the model did not learn from negation-adjacent training
data.

### Class: `wrong_rewrite_dir` / `lean_syntax_error` (rewrite_succ family)

**`rewrite_succ_0`** (held family `rewrite_succ`)

The seq2seq emits short `rw [...]` candidates pointing at hypotheses that do
exist, but the **direction** of the rewrite is wrong for the goal's RHS — or
the candidate is truncated before the close bracket and fails to parse. This
is the family v7 identified as having no same-operation sibling in train,
and the v8 seq2seq inherits the same gap.

### Class: `type_mismatch`

**`forall_inst_*`**: top candidates like `exact Eq.symm h` or `exact h` —
type-correct *shapes* (function application) but the wrong term for the
target's specific instantiation. The seq2seq beam contains no `exact h N`
substituting the goal's literal — the basic corpus does not teach that
shape.

## 3. Reading the failures

- **Cross-family transfer worked** exactly when the seq2seq's training
  distribution contained a *slot-compatible* tactic shape. Every verified
  candidate was a slot fill of a shape `⟨N, rfl⟩` it had seen in
  `exists_witness`.
- **Cross-family transfer failed** when the held family's tactic shape was
  *unique* in the corpus. `forall_inst`'s `exact h N`, `neg_exfalso`'s
  `exact absurd hp hnp`, and `rewrite_succ`'s `rw [h]` chains have no
  surface-similar cousin in the train pool — the seq2seq emits adjacent shapes
  but never the right one.
- **`novel_verified = 0`** confirms the model is not synthesising new tactic
  strings; it is *reusing* training-distribution strings with different
  literal slots. The path to non-zero novel verifications is *training
  data* (a larger Lean tactic corpus or a real LLM), not architecture
  changes to this small CPU seq2seq.
