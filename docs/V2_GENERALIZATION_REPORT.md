# Mini-ELF v2 — Generalization / Robustness Study

**v2 is not a new model — it is a stress test.** v1 posted strong numbers on the
basic corpus (test `pass@1` 0.89, `pass@5` 0.95), but that corpus is small and
**templated** (≥5 near-identical variants per family, constant hypothesis names).
v2 asks the honest question: *does any of that survive distribution shift?* It (1)
builds a harder, less-templated corpus, (2) adds adversarial / family-aware /
difficulty split strategies, (3) evaluates the **existing** v1 model on the hard
corpus with no retraining, and (4) trains a v2 model on the combined corpus to see
whether harder training data recovers the lost generalization.

> Scope, unchanged: **theorem-level** verification only (`state_after_is_real=false`);
> Mini-ELF v0/v1/v2 are prototypes of the *generation loop*, **not** full ELF over
> proof states; LeanDojo `run_tac` remains blocked (`xfail`); witness-copy is
> symbolic augmentation; `nn` decode is retrieval. **16–96 eval rows per split →
> directional, never statistically definitive.**

## 1. The hard corpus

Generated by `scripts/generate_hard_corpus.py` (core Lean 4, no Mathlib), collected
+ Lean-verified exactly like the basic corpus.

| quantity | value |
| --- | --- |
| theorem seeds | 94 |
| pattern families | 14 (compositional: multi-step implication, nested ∧, ∨-elim/case-split, iff chains/direction, eq chains, ∃-witness with unseen literals) |
| difficulty | 69 hard / 25 medium |
| candidate attempts | 376 |
| verified / failed | 204 / 172 (0 timeouts) |
| candidate success rate | 0.54 |
| **zero-success theorems** | **0** (every theorem has ≥1 verified tactic — 100% coverage) |

Failures are legitimate Lean rejections (type mismatch, invalid projection, `rfl`
on a non-reflexive goal) from the deliberate near-miss candidates — exactly the
hard negatives the reranker analysis needs. Vs the basic corpus the hard corpus
adds **unseen numeric witnesses** (10, 13, 42, 100), **3-step implication chains**,
**nested conjunction projection** (`h.2.2`, `h.1.2`), **`∨`-elimination case
splits**, and **iff/equality composition**.

## 2. Split strategies (`src/mini_elf_lean/splits.py`)

| strategy | rule | purpose |
| --- | --- | --- |
| `hash` | per-theorem hash (existing) | in-distribution baseline |
| `family_holdout` | whole families → one split | out-of-family generalization |
| `difficulty_holdout` | easy/medium → train, hard → val/test | compositional generalization |
| `adversarial_sibling` | train one sibling family, eval the other (`and_elim_left`↔`right`, `iff_mp`↔`mpr`, `or_intro_left`↔`right`, `nested_and_elim_r`↔`l`, `iff_apply`↔`flip`) | relational generalization |

All four build leakage-free datasets (verified: 0 train/val/test theorem overlap)
for both the hard corpus and the combined (basic+hard) corpus. `build_dataset.py`
gained `--split-strategy` / `--seeds` / `--corpus-source`; rows now carry a
`metadata` block (`pattern_family` / `difficulty` / `corpus_source`).

## 3. Headline finding — v1 does NOT transfer

The basic-corpus v1 model (`decoder_rerank_witness`, **no retraining**) evaluated
on the hard corpus test splits, lean-cli `pass@k`:

| split | n | pass@1 | pass@3 | pass@5 | invalid@1 | novel_verified | witness verified |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **basic test (in-distribution)** | 38 | **0.89** | 0.95 | **0.95** | 0.11 | 2 | 2/2 |
| hard hash | 26 | 0.08 | 0.23 | **0.23** | 0.92 | 8 | 8/8 |
| hard difficulty_holdout | 96 | 0.04 | 0.06 | **0.06** | 0.96 | 12 | 2/6 |
| hard adversarial_sibling | 38 | 0.00 | 0.11 | **0.11** | 1.00 | 8 | 8/8 |
| hard family_holdout | 39 | 0.00 | 0.00 | **0.00** | 1.00 | 0 | — |

**The learned generator + reranker collapse under distribution shift** (`pass@5`
0.95 → 0.00–0.23); `invalid@1` jumps to 0.92–1.00. This confirms v1's basic-corpus
numbers were substantially **inflated by overfitting a small templated
distribution**. Per-difficulty: v1 still clears *medium* hard-corpus theorems
(`pass@5` 0.75 on the hash split — these resemble basic families) but **scores 0.00
on the genuinely hard, multi-step ones**.

**What *does* transfer is the symbolic witness-copy.** On hash/adversarial it
verifies 8/8 witness candidates and yields the only `novel_verified` (copying
unseen literals `6`/`9`/`42` into `exact ⟨N, rfl⟩` / `refine ⟨N, ?_⟩; rfl`). The
non-neural augmentation is distribution-robust; the neural components are not.

### Reranker generalization (calibration)

| split | mean score: verified | mean score: failed |
| --- | --- | --- |
| basic test | 0.97–1.0 | 0.21–0.30 |
| hard hash | 1.00 | 0.45 |
| hard difficulty_holdout | 0.85 | 0.47 |
| hard family_holdout | — (0 verified) | 0.59 |

Under shift the reranker keeps scoring the *few* verified candidates high but
**floats failed candidates from ~0.25 → ~0.45–0.59** — it is much less
discriminative off-distribution, which is precisely why `invalid@1` explodes. On
unseen families it scores Lean-failures at 0.59 with **nothing** verifying. (Full
taxonomy + examples: [`V2_FAILURE_EXAMPLES.md`](V2_FAILURE_EXAMPLES.md).)

### Failure taxonomy (failed top-1, v1 transfer)

Dominant kinds across hard splits: `missing_multistep` (emits `h2 (h1 hp)` instead
of the full `h3 (h2 (h1 hp))` chain), `wrong_iff_direction`, `wrong_equality_direction`,
`wrong_witness` (`exact ⟨1, rfl⟩` for `∃ n, n = 6`), and `unknown`. The
multi-step / compositional families are where v1 has essentially no signal.

## 4. Mini-ELF v2 — does combined training help?

v2 = the **same v1 architecture** (denoising AE + structured flow + verifier-aware
reranker + witness-copy) trained on the **combined** basic+hard corpus
(`scripts/train_mini_elf_v2.py`; AE 100 / flow 500 / rerank 100 epochs, reranker
on both corpora's traces + 1,834 self-training hard negatives). One model per
split strategy so every eval is leakage-free. lean-cli `pass@k`,
`decoder_rerank_witness`:

| eval | n | pass@1 | pass@3 | pass@5 | invalid@1 | novel_verified | witness |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **basic test** (regression check) | 38 | 0.71 | 0.82 | 0.82 | 0.29 | 2 | 4/4 |
| **hard hash** (in-distribution) | 26 | 0.85 | 0.92 | **1.00** | 0.15 | 8 | 8/8 |
| **hard difficulty_holdout** | 96 | 0.06 | 0.06 | **0.06** | 0.94 | 0 | 0/4 |
| **hard adversarial_sibling** | 89 | 0.39 | 0.42 | **0.53** | 0.61 | 20 | 10/10 |

Comparison to v1-transfer (same hard test splits):

| split | v1 transfer pass@5 | v2 pass@5 | Δ |
| --- | --- | --- | --- |
| hard hash | 0.23 | **1.00** | **+0.77** |
| hard adversarial_sibling | 0.11 | **0.53** | **+0.42** |
| hard difficulty_holdout | 0.06 | 0.06 | **±0.00** |

**v2 is not a uniform win — and that is the honest, interesting result:**

1. **In-distribution recovery is dramatic.** On `hard hash`, adding hard data to
   training lifts `pass@5` 0.23 → **1.00** and cuts `invalid@1` 0.92 → 0.15. When
   the test theorems have same-family neighbours in training, the v1 *method*
   works fine on hard problems — v1's collapse in §3 was a **data-coverage**
   failure, not an architectural one.
2. **No compositional generalization.** `difficulty_holdout` (train easy/medium,
   test hard) stays at `pass@5` **0.06** — identical to v1-transfer. Training on
   simpler problems does **not** teach the model to compose multi-step proofs it
   never saw. This is the hard open problem.
3. **Partial relational generalization.** `adversarial_sibling` recovers to
   `pass@5` 0.53. Per-family sibling top-1 accuracy under the adversarial split:
   `eq` 1.00, `imp` 1.00, `iff` 0.50, but **`and_elim` 0.00 and `or_intro` 0.00** —
   the model transfers the *lexical* sibling flips but still cannot do the purely
   *relational* and/or flips when the exact family is held out.
4. **Training on harder data REGRESSES the basic corpus** (`pass@5` 0.95 → 0.82,
   `invalid@1` 0.11 → 0.29). A small fixed-capacity model spread over a more
   diverse corpus trades in-distribution precision for breadth — a real cost, not
   hidden.
5. **Witness-copy stays robust everywhere** (8/8, 10/10, 4/4); on
   `adversarial_sibling` it drives `novel_verified` to **20**.

(`family_holdout` was evaluated for v1-transfer only — `pass@5` 0.00. A v2
`family_holdout` model was **not** trained: the `difficulty_holdout` result above
already shows that holding out whole groups is not recovered by combined training,
so the extra ~20-min run was not spent. This is a deliberate, stated scope cut,
not a hidden failure.)

**Generalization gap** `basic_test − hard_test` (pass@5): v1 = 0.95 − 0.23 =
**+0.72** (severe overfit); v2 = 0.82 − 1.00 = **−0.18** (the gap closes and even
inverts on the hash split, because v2 now has hard-family training coverage while
basic regressed). The gap on the *holdout* splits (difficulty/adversarial) remains
large — generalization to genuinely unseen structure is unsolved.

## 6. Honest conclusions

- v1's basic-corpus headline (`pass@5` 0.95) **does not generalize**: under
  distribution shift the learned generator+reranker drop to `pass@5` 0.00–0.23.
  This is the central, intended result of the v2 study.
- The **symbolic** witness-copy is the only v1 component that transfers — a useful
  reminder that explicit structure-copying beats learned weights out-of-distribution
  on this tiny corpus.
- The reranker is **mis-calibrated off-distribution** (verified/failed scores
  collapse together), so it admits invalid top-1 candidates it would have rejected
  in-distribution.
- Everything remains theorem-level, small-sample, and a generation-loop prototype —
  **not** full ELF over proof states.

## 7. What remains for v3

1. Lift the *generator* (not just the reranker) toward compositional proofs
   (multi-step chains, case splits) — the families where v2 still has no signal.
2. A real-LLM candidate pilot on the hard corpus (needs an API key).
3. A larger, naturally-occurring (non-templated) corpus so numbers stop being
   dominated by template coverage.
4. Real next-state supervision once the LeanDojo `run_tac` blocker is lifted — the
   prerequisite for modeling actual proof-state flow.
