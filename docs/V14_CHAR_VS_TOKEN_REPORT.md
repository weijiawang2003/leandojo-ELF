# Mini-ELF v14 — Char vs Token Comparison

Companion to `V14_TOKEN_SEQ2SEQ_REPORT.md`. This document side-by-sides
v13 char-level (the warm-verifier corrected baseline) against the v14
token-level model under four configurations, on the same v11
family-LOFO test rows. Every number is generated by
`scripts/compare_v13_v14.py --ensemble`; results live in
`data/baselines/v14_token_seq2seq/comparison.json`.

## 0. The four configurations

| label | description |
|---|---|
| **A. v13 char + LA + warm** | v11 char seq2seq beam + v12 literal_aware_decode + v12 reranker, lean-cli verified with v13's 120-s warm verifier. This is the v13 headline. |
| **B. v14 token raw + warm** | v14 token seq2seq beam (`beam_width=10`), no post-processing, lean-cli verified at 120 s + v14 warm rerun at 180 s. |
| **C. v14 token + LA + warm** | v14 token beam + v12 literal_aware_decode + v12 reranker (reused unchanged), lean-cli verified at 120 s + warm rerun at 180 s. |
| **D. ensemble (char ∪ token) + LA + rerank** | char raw beam (10) ∪ token raw beam (10) → dedup → LA + rerank → re-verify. See §3 for caveat. |

## 2. Modelling-side audit (independent of pass@k)

Counts over **350 candidates total** = 5 families × n_test_rows ×
beam_width 10. *(Per-row totals vary by family because v14 uses every
test variant; the rate columns normalise this.)*

| metric | char (v13) | token (v14) | Δ |
|---|---:|---:|---|
| fused-keyword tokens (`refintro`/`rwexact`/…) | non-zero on forall_inst_var_m (seen in beam) | **0 across all families** | **token-level invariant achieved** |
| char-truncation patterns (`exact h.` / `rw [hns` / `cases h wi`) | observed on forall_inst, exists_reconstruct beams in v8/v11 | absent on every family except neg_exfalso (5/n) | substantially reduced |
| `exact h <num>` schema-present rate (forall_inst) | model emits this only for trained literals | 28.6 % of forall_inst candidates | similar (the v12 literal-adapt module fills the gap on both) |
| `rw [h]` schema-present rate (rewrite_succ) | high (raw beam dominated by `rw [h]`) | 12.0 % of rewrite_succ candidates (cleaner token-stream variety) | similar |

The headline modelling change is **fused-keyword tokens = 0**. v8/v11
char output contained `refintro hn`, `rwexact h`, `refin rfl⟩` on the
`forall_inst_var_m` beam; v14's token vocabulary makes these
unrepresentable.

## 3. Ensemble caveat

The ensemble row in §1 column D was computed in lower-bound mode (no
warm rerun) because the warm-rerun script only walks v14's predictions,
not the ensemble's. The interesting comparison is `A vs C` (the two
headline configurations); the ensemble is an exploratory data point.

Two facts about D that show why it underperforms:

1. **Char-first precedence pushes token candidates past top-10 on
   `neg_imp_exfalso`.** The char beam is placed first in the dedup'd
   list (the calibrated baseline). On neg_imp_exfalso the char beam
   has no verifying candidate; the token beam does, but it lands at
   beam positions 11+ after dedup and never sees the reranker.
2. **The reranker is the same v12 module on the same merged beam,
   so its neg_imp_exfalso mis-calibration applies again.**

A future v15 ensemble would benefit from (a) a learned re-ranker that
penalises stale char-truncations and rewards verifying contrapositive
shapes, and (b) interleaving char/token beams instead of
concatenating.

## 4. Per-row comparison: what each configuration solves

Per the v11 family-LOFO test set (uniques only, deduplicated to match
v12/v13 row counts):

### forall_inst (7 unique rows)

| theorem | A. v13 char+LA | C. v14 tok+LA | who fixes it |
|---|:---:|:---:|---|
| forall_inst_7_0 | ✓ (raw `exact h 7`) | ✓ (raw) | both |
| forall_inst_3_0 | ✓ (raw + literal-adapt agree) | ✓ (literal-adapt + warm) | both |
| forall_inst_5_2 | ✓ (literal-adapt + warm `exact h 5`) | ✓ (literal-adapt + warm) | both |
| forall_inst_9_4 | ✓ (raw `exact h 9`) | ✓ | both |
| forall_inst_13_6 | ✓ (literal-adapt + warm `exact h 13`) | ✓ (literal-adapt + warm) | both |
| **forall_inst_var_m** | ✗ (beam dominated by char-truncations) | ✓ (token beam emits `exact h` cleanly → literal-adapt → `exact h 8`) | **v14 only** |
| forall_inst_var_k | ✓ (literal-adapt + warm `exact h 8`) | ✓ (literal-adapt + warm) | both |

**v14 fixes the one row v13 couldn't (forall_inst_var_m), gains zero
losses → 7/7.**

### neg_imp_exfalso (5 unique rows × 3 variants = 15 total rows)

| theorem | A. v13 char+LA | B. v14 tok raw | C. v14 tok +LA | who fixes it |
|---|:---:|:---:|:---:|---|
| neg_imp_exfalso_pq | ✗ | ✓ | ✗ at p@5 (✓ at p@10) | v14 raw |
| neg_imp_exfalso_ab | ✗ | ✗ at p@5 (✓ at p@10) | ✗ at p@5 (✓ at p@10) | v14 at p@10 |
| neg_imp_exfalso_xy | ✗ | ✓ | ✗ at p@5 (✓ at p@10) | v14 raw |
| neg_imp_exfalso_mn | ✗ | (varies by variant) | similar | partial |
| neg_imp_exfalso_ps | ✗ | (varies) | similar | partial |

Raw token beam pass@5 = 9/15 = 0.600 = 3/5 if deduplicated.
After warm rerun: pass@5 = 12/15 = 0.800 = 4/5 if deduplicated.

The token model **emits the correct contrapositive proof
`intro hp\n  exact absurd hp hnp` on every neg_imp_exfalso row's
beam**. Pass@5 depends only on whether this candidate lands at rank
≤5 (the reranker disrupts it; raw doesn't).

## 5. Mean comparisons

| metric | v13 char + LA + warm | v14 token + LA + warm | Δ |
|---|---:|---:|---:|
| mean pass@1 | unchanged | similar pattern | |
| **mean pass@5** | **0.696** | **0.765** | **+0.069** |
| **mean pass@10** | 0.696 | **0.925** | **+0.229** |
| verified candidates (sum across folds) | 70 | 75 (raw) / 75 (+LA) | small lift |
| **novel_verified (sum)** | 7 | **30** | **+23** |
| fused-keyword candidates | non-zero | **0** | invariant achieved |

The pass@10 number (+0.229) is the most honest summary of v14's
capability: the token model **emits verifying candidates** on
families v13 couldn't; the v12 reranker just doesn't always promote
them. A v15 learned reranker would convert pass@10 into pass@5 here.

## 6. What v14 doesn't change

* **`rewrite_succ`** preserved at 1.000 (raw, +LA, ensemble all
  match v13).
* **`exists_reconstruct`** preserved at 1.000 (+LA + warm).
* **`neg_exfalso`** unchanged at 5/8 = 0.625 across all configs;
  the family-LOFO holdout removes the dual-hypothesis witness shape
  the model would need.
* **v12 metrics on disk** untouched — `tests/test_v12_eval.py` still
  passes its PINNED tuples.
* **v13 metrics on disk** untouched — `tests/test_v13_timeout_rerun.py`
  still passes.
